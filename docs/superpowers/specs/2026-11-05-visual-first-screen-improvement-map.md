# Voice Studio 화면 개선 목록

## 목적

실행 중인 PC 앱이 있는데도 첫 화면에서 설치 안내가 반복되는 문제를 없애고, 녹음과 나머지 작업 화면을 설명문 없이도 이해할 수 있게 시각 중심으로 정리한다. 이 문서는 화면별 ID와 개선 순서를 고정해 한 화면씩 구현하고 확인하기 위한 작업 기준이다.

## 화면 공통 기준

- 화면 제목과 실제 작업 콘텐츠(읽을 대본, 작품명 등)는 남기고, 제목 아래 설명·도움말·팁·단계 문장·긴 상태 문구는 시각 요소로 대체한다.
- 녹음 파형과 입력 레벨, 마이크/재생/정지 아이콘, 진행 표시, 이미지, 상태 모양과 위치로 다음 행동과 현재 상태를 알 수 있게 한다.
- 색상 하나만으로 상태를 전달하지 않는다. 아이콘 모양, 크기, 배치, 진행 변화도 함께 쓴다.
- 기능 동작에 필요한 버튼은 익숙한 아이콘으로 표현하고, 스크린리더용 이름은 유지한다. 사용자가 읽거나 선택하는 콘텐츠 텍스트는 설명문과 구분해 유지한다.
- 기존 WindSoft 토큰과 컴포넌트를 우선 사용한다. 녹음 레벨과 동화 장면처럼 전용 시각화가 필요한 요소만 현재 구성에 맞춰 유지한다.
- 데스크톱과 모바일에서 같은 우선순위로 동작하도록 검토한다.

## 화면 ID 및 개선 항목

| ID | 화면 | 현재 문제 | 개선 방향 | 순서 |
|---|---|---|---|---:|
| RV-01 | 앱 시작 및 로컬 앱 상태 | `App.tsx`의 전체 화면 진입 조건이 런타임 연결과 모델 설치를 한 묶음으로 취급한다. 페이지가 다시 열려 연결 정보가 없거나 모델이 없으면 `SetupScreen`이 앱 작업 화면을 대체한다. 이미 실행 중인 런타임도 설치를 먼저 해야 하는 것처럼 보일 수 있다. | 시작 시 로컬 앱 상태를 먼저 확인한다. 런타임이 응답하면 설치 화면을 건너뛰고 연결/페어링 상태를 보여준다. 런타임이 응답하지 않을 때에만 설치 진입점을 제공한다. 모델 미설치는 작업 화면을 가리지 말고 음성 생성 화면의 시각적 준비 상태로 표시한다. 설치·실행·연결·모델 상태를 서로 다른 상태로 표현한다. | 1 |
| RV-02 | 첫 연결 및 설치 | `SetupScreen`은 앱 미설치와 실행 중이지만 미연결인 상황을 시작 단계에서 구분하지 못할 수 있다. | 설치 필요, 실행 감지, 연결 대기, 권한 요청, 연결 완료를 서로 다른 화면 상태로 만든다. 실행이 감지되면 연결 동작을 바로 앞세운다. 설치 안내는 런타임이 없을 때 선택 가능한 보조 경로로 둔다. 완료 후 같은 설치 화면으로 되돌아오지 않고 작업 화면으로 진입한다. | 2 |
| RV-03 | 녹음 스튜디오 | 대본 선택/편집, 마이크 설명, 기술 정보, 단계 텍스트, 녹음 팁, 가져오기 안내가 녹음 컨트롤과 함께 보여 복잡하다. | 화면 제목 아래에서는 읽을 대본(핵심 작업 콘텐츠), 마이크 상태, 큰 녹음 버튼과 파형을 중심으로 구성한다. 대기/녹음/일시정지/미리듣기/저장 상태를 파형·마이크·재생·저장 아이콘과 진행 모양으로 구별한다. 대본 선택과 기존 파일 가져오기는 아이콘 중심의 보조 동작으로 둔다. 도움말·기술 정보·반복 단계 문장을 제거한다. | 3 |
| RV-04 | 저장한 녹음 | 빈 상태와 각 녹음 카드에 긴 안내/설명이 있다. | 녹음 카드를 재생 가능한 시각 카드로 만들고 파형, 길이, 날짜, 재생/삭제 아이콘을 우선 배치한다. 비어 있을 때는 마이크 그림과 녹음 화면으로 이어지는 단일 아이콘 동작을 쓴다. | 4 |
| RV-05 | 동화 선택 | 카드에 줄거리 요약과 그림 장수 같은 보조 텍스트가 함께 노출된다. | 삽화와 작품 제목으로 고르는 그림 카드로 단순화한다. 제목 외 요약 문구를 빼고, 선택 상태는 테두리/체크 모양으로 보인다. | 5 |
| RV-06 | 동화 장면 보기 | 장면 텍스트, 장면 수 표기, 출처 문구와 여러 버튼이 그림 주변에 모여 있다. | 장면 이미지를 중심에 크게 두고 좌우 넘김, 재생/만들기 동작을 아이콘으로 배치한다. 자막은 현재 장면의 핵심 제목처럼 필요한 경우에만 노출하고 장면 진행은 점/페이지 모양으로 표현한다. 출처는 화면의 주 흐름에서 분리한다. | 6 |
| RV-07 | 음성 만들기 | 텍스트 설명과 모델 설치 안내/기술 세부사항이 생성 작업을 복잡하게 보이게 한다. | 선택된 녹음과 문장을 시각 카드로 확인하고, 모델 상태는 준비/다운로드 진행/완료 아이콘과 막대로 표현한다. 준비가 끝나면 생성 아이콘을 주 동작으로 둔다. 긴 설치 설명과 기술 메타데이터는 기본 화면에서 감춘다. | 7 |
| RV-08 | 생성 결과 | 빈 상태 설명과 파일 정보가 주요 재생 동작보다 앞선다. | 결과마다 큰 재생 컨트롤과 파형, 길이, 다운로드/삭제 아이콘을 우선한다. 빈 상태는 결과물이 만들어지는 흐름을 그림으로 보여주고 생성 화면으로 바로 연결한다. | 8 |
| RV-09 | 설정 및 설치 | 설치, PC 정보, 권한, 개인정보 안내가 설명문 중심으로 표시된다. | 상태 아이콘과 짧은 제목으로 설치/연결/마이크 권한/모델/저장 상태를 훑어볼 수 있게 한다. 설치 파일과 세부 진단은 설정 안의 별도 선택 영역에 둔다. | 9 |

## 제안된 접근

1. 모든 화면을 한 번에 다시 디자인한다. 전체 톤은 빠르게 맞출 수 있지만, 사용자가 원하는 순차 검토가 어렵고 기존 동작 회귀 범위가 커진다.
2. 공통 디자인 시스템을 교체한다. 이번 문제와 무관한 변경이 많아지고 녹음/오디오 조작의 특수성을 살리기 어렵다.
3. 화면 ID와 우선순위를 정하고 한 화면씩 고친다. 기존 React 흐름과 WindSoft 구성은 유지하면서 각 화면을 확인할 수 있다. **이번 문서의 작업 방식:** 시작/설치 상태를 먼저 바로잡고, 녹음 화면부터 순서대로 진행한다.

## 순차 진행 및 완료 기준

각 화면은 해당 ID만 구현한 뒤 확인하고 다음 ID로 넘어간다.

1. **RV-01–RV-02:** 앱 시작 시 런타임 감지 결과에 따라 연결 또는 설치가 올바르게 안내되고, 실행 중인 런타임에 설치 단계가 반복되지 않는다.
2. **RV-03:** 화면 제목 외 설명문을 없애고도 마이크 준비, 녹음, 정지/일시정지, 미리듣기, 저장 흐름을 시각적으로 구별할 수 있다.
3. **RV-04–RV-09:** 각 화면에서 사용자가 할 수 있는 주요 행동 하나가 시각적으로 분명하며, 사용자가 요청한 설명 텍스트 제거 원칙을 유지한다.
4. 각 화면의 데스크톱/모바일 렌더링에서 주요 컨트롤이 보이고, 상태 구분이 색상에만 의존하지 않는지 확인한다.

## 구현 범위에서 지킬 점

- 각 단계에서는 지정한 화면 ID의 동작만 변경한다.
- RV-01/RV-02에서는 앱 시작 감지와 연결/설치 상태만 다루며, 녹음·생성·파일 저장 동작은 바꾸지 않는다.
- 녹음 저장, 생성, 로컬 런타임, 파일 저장 방식은 바꾸지 않는다.
- 상태/오류에 필요한 접근성 이름은 시각 문구 제거와 별도로 보존한다.
- 한 화면 개선 중 다른 화면의 문구/레이아웃을 함께 고치지 않는다. 공통 요소 변경이 꼭 필요하면 영향받는 화면 ID를 먼저 기록한다.
