# Voice Studio 화면 개선 목록

## 목적

현재 구현된 화면을 기준으로 실제로 고칠 내용을 화면 ID별로 정리한다. 화면 제목과 사용자가 읽거나 고르는 콘텐츠는 유지하고, 설명·도움말·기술 정보는 배치, 크기, 상태 표시, 아이콘, 그림, 진행 UI로 바꾼다. 각 ID는 한 화면씩 작업할 때의 범위다.

## 공통 디자인 방향

- 화면 제목 외 안내 문장은 기본 화면에서 제거한다. 문장이 알려주던 순서와 다음 행동은 시각적 그룹, 연결, 활성 상태, 진행 표시로 옮긴다.
- 대본, 사용자가 입력한 문장, 작품명, 이야기 자막, 오류와 작업 상태처럼 작업 결과나 선택에 필요한 내용은 콘텐츠로 유지한다. 필드 설명은 폼 레이아웃과 아이콘으로 대신하고, 아이콘의 스크린리더 이름은 보존한다.
- 현재 `var(--font-size-body)`를 사용하는 일반 문구·버튼이 많다. 조작 버튼과 입력 텍스트는 16px 이상을 기준으로 키우고, 작은 보조 표기는 실제로 필요한 경우에만 둔다. 페이지 제목과 섹션 제목은 서로 분명한 크기 차이를 둔다.
- 데스크톱은 주 작업이 화면 중앙에만 뭉치지 않도록 콘텐츠 최대 폭과 좌우 비율을 정한다. 모바일에서는 좌우 패널을 작업 순서대로 쌓고, 핵심 조작이 첫 화면에 들어오게 한다.
- 색만으로 상태를 나타내지 않는다. 모양, 아이콘, 위치, 진행 막대를 함께 사용한다. 텍스트를 없애도 상태·오류는 접근 가능하게 전달한다.

## 실제 배포 브라우저 재점검

- 2026-11-07 Windows Chrome에서 `https://recording-voice-web.vercel.app`을 Agent Desktop MCP로 열었다. 데스크톱 캡처는 1920×1020, 좁은 화면 캡처는 브라우저 콘텐츠 약 514 CSS px 폭으로 확인했다.
- Windows 로컬 앱 감지, `이 PC에 연결`, 녹음 스튜디오 진입, 마이크 확인까지 동작했다. 마이크 정보에는 `48,000 Hz · 1채널`이 나타났다. 동화책, 저장한 녹음, 음성 생성, 생성 결과, 설정 화면도 열렸다.
- 마이크 연결과 화면 탐색은 확인했지만 이번 점검에서 녹음·저장·재생은 실행하지 않았다. 아래 화면 진단은 이 실제 배포 화면에서 본 구성과 상태 전이를 기준으로 한다.
- 여러 작업 화면에 공통으로 상단의 `로컬 연결됨` 배지와 큰 초록 연결 배너가 동시에 표시된다. 상태가 정상일 때는 연결 상태가 중복되고 작업 영역의 세로 공간을 차지한다. 연결 오류/권한 필요 상태에서만 큰 배너를 쓰고, 정상 연결은 상단의 작은 배지 하나로 표시한다.

| **RV-06** 동화 장면 보기 | 실제 장면에서는 큰 삽화 위를 반투명한 두 줄 자막이 덮는다. `1 / 3 장면` 표시와 아래의 세 개 진행 점이 진행을 중복해서 알린다. 장면 이동 컨트롤은 그림 아래에 있고, `이 이야기로 음성 만들기` 동작은 더 아래라 첫 뷰포트에는 들어오지 않는다. 1920×1020에서도 그림과 자막이 화면 대부분을 차지한다. | 이미지 아래에 읽기 자막을 두어 그림을 덮지 않게 한다. 장면 번호 문구는 지우고 현재 점과 짧은 진행 막대 하나로 위치를 표현한다. 이전/다음은 그림 좌우의 큰 화살표로 옮기되 끝 장면에서는 비활성 모양과 접근 가능한 이름을 유지한다. `이 이야기로 음성 만들기`는 작은 화면에서도 장면 조작 다음에 바로 보이도록 뷰어 하단에 붙인다. 그림 출처는 정보 아이콘 상세로 이동한다. |
| **RV-07** 음성 생성 | 실제 생성 화면에서 큰 초록 연결 배너, 단계 문구, 페이지 설명, `생성 설정` 카드 설명, 목소리/모델의 필드 도움말이 입력 사이에 반복된다. 데스크톱에서도 생성 폼이 한 장의 전체 폭 카드이고, 좁은 화면 첫 뷰포트에는 읽을 목소리 선택만 보이며 문장과 생성 동작은 아래로 밀린다. 이 PC에는 모델이 이미 설치돼 있어도 현재 모델 상태는 select 옵션 텍스트 안에만 표시된다. | 정상 연결 배너와 단계·카드 설명·필드 도움말을 제거한다. 제목 바로 아래에 목소리 카드와 문장 입력을 두고 첫 화면에서 문장과 생성 버튼까지 접근할 수 있게 한다. 데스크톱은 입력 60%, 모델/작업 상태 40%로 나누고 모바일은 생성 버튼을 문장 바로 아래에 배치한다. 설치된 모델은 체크 상태 하나로 표시한다. 미설치 때만 설치 크기/라이선스/저장소를 상세 영역으로 펼치고, 다운로드 중에는 진행 막대와 숫자만 남긴다. 오류 문구는 유지한다. |
| **RV-08** 생성 결과 | 실제 결과 두 건이 데스크톱에서 긴 카드 두 장으로 세로 나열된다. 날짜 전체 문자열, 길이/샘플레이트/생성시간, 긴 대본, 재생 버튼, 모델/준비시간, 삭제가 같은 수준으로 보여 재생보다 메타데이터가 두드러진다. 모바일 첫 화면에는 첫 결과의 대본과 재생 버튼 일부만 보인다. | 긴 대본 때문에 목록은 한 열로 유지하되 카드의 날짜/길이/재생/삭제를 한 줄 도구 영역에 모으고 대본을 그 아래 넓게 둔다. 큰 재생 아이콘과 파형을 첫 동작으로 보여준다. 모델, 샘플레이트, 생성/준비 시간은 정보 아이콘 상세로 접는다. WAV 다운로드와 삭제는 아이콘으로 표현하고 접근성 이름은 유지한다. 결과가 없을 때는 파형 그림과 생성 이동 버튼 하나만 둔다. |
| **RV-09** 설정·설치 | PC 앱이 `연결됨`인 실제 화면에서도 첫 설정 탭은 `설치 및 연결`이고 본문 제목은 `Windows 설치 안내`다. 이미 동작하는 PC에서 설치가 다음 할 일처럼 보인다. 다운로드 링크는 어두운 배경에서 글자와 경계가 약하다. 좁은 화면에서는 설정 메뉴 링크가 사라지고 상단 `?` 도움말 버튼을 통해서만 설정에 들어갈 수 있다. | 연결 상태에 따라 첫 설정 탭을 분기한다. 연결됨이면 `PC 환경` 상태 요약을 먼저 열고, 연결 전이면 설치/연결을 첫 탭으로 둔다. 다운로드 동작은 설치가 필요한 상태에만 강조하고 텍스트/버튼 대비를 올린다. 모바일 상단 메뉴에 설정 톱니바퀴를 직접 표시하고 `?`는 도움말 용도로 분리한다. 실행 자원은 수치 게이지/상태 모양으로, 개인정보 흐름은 브라우저→이 PC 저장 그림으로 설명 문단을 대체한다. |

## 화면 작업 순서

1. **RV-01–RV-02:** 시작 상태와 PC 앱 연결/설치 분기를 먼저 정리한다. 현재 계속 보이는 `PC 앱에 연결해요` 제목과 실행 중인 PC 앱 감지 상태의 불일치를 해결한다.
2. **RV-03:** 대본과 녹음 조작을 55:45 작업 화면으로 재배치하고 팁·단계·반복 설명을 시각 UI로 옮긴다.
3. **RV-04–RV-09:** 위 표에 적힌 각 화면의 구체 수정 사항을 ID 단위로 적용한다.

## RV-01–RV-02 1차 수정 결과

- 시작 제목을 런타임 확인 중, 감지됨, 연결 중, 미감지 상태에 맞춰 표시하고 상태 카드 제목과 브랜드 부제를 제거했다.
- 정상 감지 화면에는 체크 모양과 연결 버튼만 두고, 연결 요청 중에는 진행 표시를, 미감지 화면에는 경고 모양·재시도·설치 동작을 둔다. 설치 안내는 선택했을 때만 열린다.
- 설치 안내의 긴 절차 설명은 빼고 Windows 설치 파일, 설치 안내 링크, 설치 후 다시 확인 동작을 남겼다.
- 2026-11-07 Windows Chrome Agent Desktop MCP로 로컬 개발 화면을 1920 px와 650 px 창 폭에서 확인했다. 상태 카드와 두 동작이 좁은 화면에도 함께 보이고 가로 잘림은 없었다. 이 로컬 브라우저 세션에서는 Windows 런타임이 감지되지 않아 미감지 상태를 캡처했다. 배포 화면의 실행 중 감지와 연결 동작은 위 배포 재점검에서 별도로 확인했다.
- 실제 녹음 데이터 흐름은 바꾸지 않았다. 다음 작업 ID는 RV-03 녹음 스튜디오다.

## RV-03 녹음 스튜디오 1차 수정 결과

- 위 배포 화면에서 확인한 실제 위치와 중복 정보를 바탕으로 녹음 설명, 단계 번호, 긴 팁, 복제 대본 미리보기, 정상 연결 배너를 걷어냈다.
- 대본과 녹음 콘솔을 한 카드 안에서 데스크톱 55:45로 나누고, 모바일에서는 대본 다음 마이크 입력 레벨·상태·타이머·녹음 버튼이 이어지도록 배치했다. 읽을 대본, 녹음 상태/시간, 오류 및 저장 결과는 유지했다.
- 녹음 환경 안내는 짧은 시각 큐로 바꾸고, 파일 가져오기는 접힌 도구로 남겼다. 기존 저장 녹음의 음성 생성 이동은 녹음 작업 뒤의 보조 버튼으로 이동했다.
- 첫 Production 배포를 좁은 브라우저 창에서 확인했을 때, 메뉴가 여러 줄이고 카드/섹션 제목이 공간을 써서 마이크와 녹음 동작이 첫 화면 아래에 남았다. 후속 Production 캡처에서 버튼 하단을 가리던 `0 / 5,000` 글자 수 표시를 제거했다. 650×930 창의 최신 좌표에서는 버튼 하단이 뷰포트 밖으로 17px 남아 있어 모바일 제목·카드 사이의 세로 여백을 추가로 줄인다.
- 마이크 녹음/저장/재생 동작 자체는 실행하지 않았다. 실제 배포 브라우저에서 시각 배치와 접근성 트리, 좁은 화면 첫 화면에 핵심 조작이 들어오는지 확인한 뒤 이 결과를 추가한다.
