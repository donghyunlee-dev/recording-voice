# Voice Studio 화면 개선 목록

## 목적

현재 구현된 화면을 기준으로 실제로 고칠 내용을 화면 ID별로 정리한다. 화면 제목과 사용자가 읽거나 고르는 콘텐츠는 유지하고, 설명·도움말·기술 정보는 배치, 크기, 상태 표시, 아이콘, 그림, 진행 UI로 바꾼다. 각 ID는 한 화면씩 작업할 때의 범위다.

## 공통 디자인 방향

- 화면 제목 외 안내 문장은 기본 화면에서 제거한다. 문장이 알려주던 순서와 다음 행동은 시각적 그룹, 연결, 활성 상태, 진행 표시로 옮긴다.
- 대본, 사용자가 입력한 문장, 작품명, 이야기 자막, 오류와 작업 상태처럼 작업 결과나 선택에 필요한 내용은 콘텐츠로 유지한다. 필드 설명은 폼 레이아웃과 아이콘으로 대신하고, 아이콘의 스크린리더 이름은 보존한다.
- 현재 `var(--font-size-body)`를 사용하는 일반 문구·버튼이 많다. 조작 버튼과 입력 텍스트는 16px 이상을 기준으로 키우고, 작은 보조 표기는 실제로 필요한 경우에만 둔다. 페이지 제목과 섹션 제목은 서로 분명한 크기 차이를 둔다.
- 데스크톱은 주 작업이 화면 중앙에만 뭉치지 않도록 콘텐츠 최대 폭과 좌우 비율을 정한다. 모바일에서는 좌우 패널을 작업 순서대로 쌓고, 핵심 조작이 첫 화면에 들어오게 한다.
- 색만으로 상태를 나타내지 않는다. 모양, 아이콘, 위치, 진행 막대를 함께 사용한다. 텍스트를 없애도 상태·오류는 접근 가능하게 전달한다.

## 실제 배포 브라우저 재점검

- 2026-11-07 Windows Chrome에서 `https://recording-voice-web.vercel.app`을 Agent Desktop MCP로 열었다. 데스크톱 캡처는 1920×1020, 좁은 화면 캡처는 브라우저 콘텐츠 약 514 CSS px 폭으로 확인했다.
- Windows 로컬 앱 감지, `이 PC에 연결`, 녹음 스튜디오 진입, 마이크 확인까지 동작했다. 마이크 정보에는 `48,000 Hz · 1채널`이 나타났다. 동화책, 저장한 녹음, 음성 생성, 생성 결과, 설정 화면도 열렸다.
- 마이크 연결과 화면 탐색은 확인했지만 이번 점검에서 녹음·저장·재생은 실행하지 않았다. 아래 화면 진단은 이 실제 배포 화면에서 본 구성과 상태 전이를 기준으로 한다.
- 여러 작업 화면에 공통으로 상단의 `로컬 연결됨` 배지와 큰 초록 연결 배너가 동시에 표시된다. 상태가 정상일 때는 연결 상태가 중복되고 작업 영역의 세로 공간을 차지한다. 연결 오류/권한 필요 상태에서만 큰 배너를 쓰고, 정상 연결은 상단의 작은 배지 하나로 표시한다.

## 화면별 현재 점검과 수정 사항

| ID | 현재 화면에서 확인한 구성과 문제 | 이 화면에서 수정할 내용 |
|---|---|---|
| **RV-01** 앱 시작·PC 연결 | 배포 첫 화면의 큰 제목은 계속 `PC 앱에 연결해요`인 반면, 런타임이 정상 감지된 카드 안에는 `PC 앱을 찾았어요`가 따로 보인다. 상단 브랜드 부제 `PC 앱 연결`, `로컬 앱`, 확인 중 설명, 연결 상태 설명, 저장 위치 안내까지 문구가 반복된다. 런타임이 살아 있어도 페어링 전까지 연결 화면에 머무는 것은 필요한 흐름이며, 실제 `이 PC에 연결`을 누르자 녹음 화면으로 이동했다. 혼란은 서로 다른 상태 제목과 중복 문구에서 생긴다. | 페이지 제목 하나를 현재 상태에 맞춰 바꾸고 카드 안에 같은 상태 제목을 중복하지 않는다. 확인 중에는 진행 링, 감지 후에는 체크 모양, 연결 오류에는 경고 모양을 사용한다. 실행 중인 앱이 감지되면 `이 PC에 연결`을 주 버튼으로 유지하고 설치 링크는 미감지일 때만 보조 동작으로 둔다. 브랜드 부제, `로컬 앱`, 확인 중 설명과 저장 위치 문장은 제거한다. 연결 성공 시에는 기존 동작대로 녹음 스튜디오로 이동한다. |
| **RV-02** 첫 연결·설치 상태 | 실제 실행 중인 Windows 런타임은 자동 감지됐고 `이 PC에 연결` 동작도 성공했다. 따라서 정상 감지 상태에서 설치 버튼을 먼저 요구하는 문제는 재현되지 않았다. 다만 연결 전 상태 화면에서는 고정된 큰 제목, 카드 상태 제목, 카드 설명이 한 화면에 동시에 노출되고 설치 안내도 텍스트 링크로 제시된다. | 확인 중, 감지됨, 연결 중, 앱 미감지, 권한 오류의 상태를 단일 중앙 카드로 정리한다. 큰 제목 하나만 상태를 말하고 카드 안에는 진행 링/체크/경고 아이콘과 필요한 조작 버튼만 둔다. 실행 감지 상태에는 `이 PC에 연결`, 미감지에는 설치 프로그램 아이콘과 다시 확인 아이콘을 배치한다. 설치 안내는 실행 앱을 못 찾았을 때에만 보인다. 페어링 코드 입력은 백엔드가 코드를 요구할 때만 나타내고, 오류는 아이콘만으로 대신하지 않고 접근 가능한 짧은 오류 문구로 보존한다. |
| **RV-03** 녹음 스튜디오 | 2026-11-07 Windows Chrome에서 재측정: 1920×1020 화면에서 상단 연결 배지와 초록 연결 배너가 중복되고, `다음 단계` 카드가 154px 높이로 녹음 카드보다 먼저 나온다. 녹음 카드 시작점은 y=721, 대본 선택은 y=869이며 마이크 입력 장치와 녹음 시작 버튼은 각각 y=1216, y=1422 아래로 첫 화면에 들어오지 않는다. 약 514 CSS px 폭에서는 브랜드/메뉴, 연결 배너, 제목, 다음 단계 카드가 첫 화면을 채워 대본·마이크·녹음 컨트롤이 하나도 보이지 않았다. 팁 카드가 데스크톱 작업 폭의 약 37%를 차지하고, 카드 설명·폼 도움말·단계 번호·녹음 팁 문장이 반복된다. | 정상 연결 초록 배너를 녹음 화면에서 제거하고 상단 상태 배지와 전용 재연결 버튼을 유지한다. 저장한 녹음의 다음 단계 동작은 주 작업 패널 뒤에 한 줄 보조 버튼으로 옮긴다. 대본 선택/입력과 녹음 콘솔을 하나의 작업 카드 안에 55:45 좌우 비율로 배치하고, 모바일은 대본 → 마이크/입력 레벨 → 상태·타이머·큰 녹음 버튼 순서로 쌓는다. 도움말 문장, 중복 대본 미리보기, 단계 번호, 기술 정보, 긴 팁과 카드 설명은 제거하고, 조용한 공간·마이크 거리·말하기 속도는 작은 시각 큐로 표현한다. 파일 가져오기는 접힌 도구 영역으로 둔다. 저장/미리 듣기·다운로드·다시 녹음 동작, 오류/저장 상태, 대본과 스크린리더 레이블은 보존한다. |
| **RV-04** 저장한 녹음 | 2026-11-07 Production에서 1건 저장 데이터를 확인했다. 상단의 `로컬 연결됨` 배지와 초록 연결 배너/`다시 연결하기`가 중복되고, 화면 제목도 상단 경로·작은 `저장한 녹음` 구분 제목·큰 제목에서 반복된다. 제목 설명 한 문장이 제목과 다시 듣기/생성 목적을 풀어쓴다. 녹음은 전체 폭 카드로 쓰지만 카드 제목의 전체 날짜·초 단위 시각과 별도 길이 줄, 긴 대본, `녹음 듣기`·`삭제` 버튼이 분리되어 있어 재생/대본/보조 메타데이터의 계층이 약하다. 실제 저장 음성은 확인했지만 재생하거나 삭제하지 않았다. | 정상 연결 배너는 공통 화면에서 숨기고 상단 배지와 재연결 아이콘을 유지한다. 상단 경로와 작은 구분 제목, 설명 문장을 없애고 H1 하나만 둔다. 목록은 한 열 전체 폭을 유지하며 카드의 긴 날짜 표기를 `월·일 시:분`으로 줄이고 파형 아이콘/날짜/녹음 길이를 한 줄 메타데이터로 묶는다. 대본은 읽기 쉬운 전체 폭으로 두고 `듣기` 동작을 시각적으로 우선한다. 삭제는 휴지통 아이콘과 접근성 이름을 쓰고, 실제 삭제 전 확인을 둔다. 빈 목록은 설명 문장 대신 파형 그림과 `첫 음성 녹음하기` 동작 하나로 정리한다. |
| **RV-05** 동화 선택 | 2026-11-07 Production을 Windows Chrome Agent Desktop MCP로 다시 열어 1920×1020과 650×930 창에서 확인했다. 제목 위에 작은 구분 문구가 있고 제목 아래 안내 문장이 두 줄로 이어진다. 모바일(캡처 콘텐츠 632×912)에서는 카드가 삽화 36%와 텍스트 64%로 가로 배치된다. 첫 카드 전체 높이는 165px, 다음 카드는 줄거리 줄 수 때문에 268px이고 삽화도 각각 163px/266px로 달라 카드 경계와 이미지 비율이 불균등하다. 작품명 외 줄거리, `그림 3장 · 짧은 줄거리`, 화살표가 모두 보여 이미지보다 설명이 먼저 읽힌다. 이번 재확인에서는 세 삽화가 로드된 상태였으며, 캐시를 비우거나 강제 새로고침하지 않아 과거 빈 회색 칸/약 4초 로드 지연은 재현하지 않았다. | 제목 위 구분 문구와 제목 아래 설명, 카드 줄거리/장수 문구를 없앤다. 카드에는 대표 삽화와 작품명만 남기고 이미지 영역을 데스크톱/모바일 모두 4:3 비율로 고정해 텍스트 길이에 따른 높이 차이를 없앤다. 로드가 늦을 때 4:3 자리를 유지하는 그림형 skeleton을, 실패할 때는 일러스트형 대체 상태를 표시한다. 카드 전체 클릭이므로 화살표는 제거하고 접근성 이름은 `작품명 선택`으로 유지한다. |
| **RV-06** 동화 장면 보기 | 2026-11-07 Production을 Windows Chrome Agent Desktop MCP로 확인했다. 1920×1020에서 뷰어 그림이 화면의 대부분을 차지하고, 두 줄 자막 상자가 삽화 중앙을 덮는다. 상단의 `1 / 3 장면`과 그림 아래 3개 점이 진행을 중복해서 알린다. 이전/다음 버튼은 뷰어 아래쪽 가장자리(y=946), 그림 출처와 `이 이야기로 음성 만들기`는 첫 화면 아래(y=1065~1082)에 있다. 650×930 창(콘텐츠 632×912)에서도 삽화가 약 420px 높이로 노출되고 다음/이전 컨트롤이 하단 경계(y=890)에 걸리며, 음성 만들기 버튼은 화면 아래(y=994)에 있다. | 두 줄 자막은 그림 위 반투명 상자에서 분리해 그림 바로 아래 읽기 영역에 둔다. `1 / 3 장면` 텍스트는 제거하고 접근성 이름이 있는 단일 진행 시각 요소로 대체한다. 이전/다음은 삽화 좌우의 큰 화살표로 이동시키고 첫/끝 장면에서는 비활성 상태를 유지한다. 그림 높이를 데스크톱/모바일 뷰포트에 맞춰 줄이고 `이 이야기로 음성 만들기`를 장면 조작 바로 다음 뷰어 영역에 둬 작은 화면에서도 빠르게 찾게 한다. 그림 출처는 정보 아이콘 상세로 접는다. |
| **RV-07** 음성 생성 | 2026-11-07 Production을 Windows Chrome Agent Desktop MCP로 1920×1020과 650×930 창에서 확인했다. 정상 연결 배너는 없어졌지만, `2단계 · 내 목소리로 읽어보기`와 H1, 긴 설명, `생성 설정` 카드 제목/설명, 목소리·모델 각각의 필드 도움말이 반복된다. 1920px 데스크톱에서도 목소리/모델 입력이 카드 전체 폭 1,437px를 차지하고, 문장 입력이 y=839, 글자 수/추천 안내가 y=981, 생성 버튼은 y=1026이라 첫 뷰포트 아래에 있다. | **RV-01–RV-02** 시작·PC 연결 | Windows 다크 모드에서 첫 연결 화면도 어둡게 렌더된다. 상태 설명을 줄인 이전 개선은 있으나 가족이 처음 보는 화면에 어울리는 온화한 인상이 부족하다. | OS 설정과 무관하게 화이트 테마를 적용한다. 연결 상태는 밝은 표면의 상태 그림/큰 연결 동작으로 보여주고, 설정 링크와 오류 접근성은 보존한다. |
| **RV-03** 녹음 | 3개 동화 대본과 마이크 장치가 네이티브 `select`다. 모바일에서는 메뉴가 아이콘만 남고, 대본은 일반 textarea여서 어떤 이야기인지와 읽을 위치가 한눈에 들어오지 않는다. | 짧은 대본 선택은 삽화/작품명 카드로 한눈에 고르고, 장치가 3개를 넘으면 가로 레일로 훑는다. 선택 대본은 책 페이지처럼 편집하고 마이크·입력 레벨·타이머·녹음/일시정지는 아이콘/상태 배치로 단순화한다. |
| **RV-04** 저장한 녹음 | 저장 대본의 마지막 `요.`가 한 줄에 혼자 남고, 대본이 메타데이터와 같은 어두운 카드 안의 일반 문단으로 보인다. | 녹음 정보/재생 조작과 분리된 밝은 책장형 대본 영역을 쓰고 한국어 문장 끝의 한 단어 고립을 줄인다. |
| **RV-05** 동화 선택 | 좁은 화면에서 3개 동화 카드가 두 열+다음 줄로 나뉘고, 동화별 삽화만으로 엄마와 아이가 함께 읽는 경험을 전달하지 못한다. | 따뜻한 흰 배경에 그림책 표지 같은 카드와 엄마-아이 함께 읽기 일러스트를 더한다. 카드에는 삽화/작품명만 남긴다. 선택지가 3개 이하면 한눈에 고르고 4개 이상이면 가로 레일로 탐색한다. |
| **RV-06** 동화 장면 보기 | 한 장면의 대본이 일반 중앙 정렬 문단으로 보이고 마지막 `지요.`가 고립된다. 삽화와 대본이 페이지처럼 구분되지 않아 읽기 리듬이 약하다. | 넓은 화면은 그림 페이지와 글 페이지가 나란한 펼친 책, 좁은 화면은 그림 다음 글 순서의 한 페이지로 표현한다. 문장 폭/크기/행간을 읽기에 맞추고 페이지 넘김 조작은 아이콘 중심으로 둔다. |
| **RV-07** 음성 생성 | 저장된 목소리와 음성 모델 선택이 네이티브 `select`로 남아 있고, 동화에서 온 문장도 보통의 폼 textarea처럼 보인다. | 저장 목소리/모델을 상태 아이콘이 포함된 선택 카드로 바꾸고, 각각 4개 이상이면 가로 레일로 전환한다. 생성할 문장은 녹음 대본과 같은 책장형 입력면을 사용한다. 설치 동의/실패 상태는 필요한 문장과 접근성 이름을 유지한다. |
| **RV-08** 생성 결과 | 실제 생성 대본에서도 끝의 짧은 `요.`가 다음 줄에 혼자 남는다. 재생 조작과 대본이 같은 결과 카드 안에서 책 읽기와 구분되지 않는다. | 재생/파일 조작은 짧은 아이콘 도구줄로 유지하고, 대본은 읽기 전용 책 페이지 표면/타이포그래피로 분리한다. |
| **RV-09** 설정·설치 | 운영체제 색상 설정에 따라 설정 화면까지 다크 테마가 된다. | 같은 고정 화이트 표면을 적용하되, 설정은 동화풍 장식을 추가하지 않고 상태/자원 대비가 높은 간결한 관리 화면으로 둔다. |

공통 조판 점검에서는 제목 `text-wrap: balance`, 대본 `text-wrap: pretty`, 한국어 어절/문장부호 줄바꿈, 좌우 패널 폭, 320/375/390/650/1024/1920px 화면을 함께 살핀다. `widows`/`orphans`를 지정하는 것으로 끝내지 않고, 실제 브라우저 캡처에서 한 단어 마지막 줄/문장부호 고립/가로 넘침/버튼 잘림을 화면별로 확인한다. 제목·작품명·대본 같은 콘텐츠, 연결/녹음/오류 상태, 스크린리더 이름은 삭제 대상인 설명 문구와 구분한다.
